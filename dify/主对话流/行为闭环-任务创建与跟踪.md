# 行为闭环｜任务创建与跟踪（Dify 工作流实现草案）

## 目标
- 将“建议”转化为“可执行任务”，并完整记录接受、开始、完成的事件链路；
- 支持温和提醒、宽限顺延与T+1复盘；
- 产出依从性指标与个性化偏好，用于下轮建议排序。

## 触发
- 来自对话LLM的“建议生成完成”事件，输入含：`userId`、`agent`、`suggestion_bundle`（Top3）。

## 输入变量（示例）
```json
{
  "userId": "u_42",
  "agent": "学业与考试压力",
  "suggestion_bundle": [
    {"title":"整理桌面10分钟","steps":["清空","分类","设置学习位"],"expectedMinutes":10},
    {"title":"番茄钟10分钟","steps":["设定10分钟","专注","休息"],"expectedMinutes":10},
    {"title":"复习清单3条","steps":["回顾","选择","写下"],"expectedMinutes":8}
  ]
}
```

## 节点设计（Dify）
1. 变量整理（Variable-Extractor）
   - 解析 `suggestion_bundle` → 生成 `behavior_tasks` 插入数组。
2. DB写入（HTTP Request / 内部Connector）
   - 批量写入 `behavior_tasks`，初始 `status=issued`，生成多个 `taskId`。
3. 事件写入（HTTP）
   - 为每个 `taskId` 写 `task_events: issued`。
4. 回答/卡片（Answer）
   - 向用户展示 Top3 任务卡，提供“接受/稍后/替换”按钮。
5. 分支（If-Else）
   - 若“接受”：写 `task_events: accepted`；进入提醒排程。
   - 若“稍后”：设置`dueAt += 2h`，写`task_events: accepted`并低频提醒。
   - 若“替换”：回到LLM生成补充建议。
6. 定时（Timer/Delay）
   - 到期-15m、到期、宽限+30m 三个提醒窗口。
7. 提醒（Tool/HTTP）
   - Push/消息中心/短信（按用户偏好），同时写入 `task_events: reminded`。
8. 执行回执监听（Block: User-Action Hook）
   - 用户点击“开始/完成/跳过”，分别写入 `started/completed/skipped` 事件，并更新 `behavior_tasks.status`。
9. T+1 回访（Timer → LLM → Answer）
   - 生成简短回访对话与1键量表（mood/stress），写 `checkins`。
10. 指标更新（HTTP）
   - 聚合 `task_events` → 更新 `adherence_metrics` 物化视图或外部看板。

## 关键请求（示例）
- 写入任务
```http
POST /api/behavior_tasks/bulk
Body: [{userId, agent, title, steps, expectedMinutes, dueAt, status:"issued"}]
```
- 写入事件
```http
POST /api/task_events
Body: { taskId, userId, type, ts, channel, payload? }
```
- 更新状态
```http
PATCH /api/behavior_tasks/{taskId}
Body: { status }
```

## 错误与重试
- DB写入失败：重试3次+死信队列；
- 定时触发失败：记录补偿任务扫描 `dueAt < now && status in [issued,accepted]`；
- 用户动作重复：事件追加但去重统计按窗口聚合。

## 权限与隐私
- 仅保存必要任务元数据与事件；
- 回执凭证（照片/音频）存储引用并脱敏；
- 支持用户一键关闭提醒或删除单条任务。
