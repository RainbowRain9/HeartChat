# 心语精灵｜主工作流（完整版）

- 依据文件：`dify/心语精灵.yml`
- 参考方案：`dify/MindGuard-总体方案-整合版.md`
- 目标：对齐“认知→行动→闭环”，梳理完整节点、路由与数据流，并指出需补齐部分。

## 主干流程（对齐 MindGuard）
- 开始 → 意图识别 → 条件分支（路由） → 下游子链路：
  - Substantive_Problem：知识检索 → 基础情感分析 → 文化语境分析 → 汇总/总结/Top3建议 →（新增）行为闭环 → 直接回复 + 后续回访
  - Risk 评估：风险评估 → 条件分支2（新增路由去向，见下）
  - Daily_Conversation（≥0.70）：SmallTalk_Agent → smalltalk_count +=1 → 直接回复
  - Question_About_System：FAQ_KB_Retrieval → FAQ_Answer →（新增）答复出口
  - Feedback：Feedback_Extractor →（新增）反馈话术生成 →（新增）反馈入库/工单 → 答复出口
  - 兜底：SmallTalk_Agent

## 已有节点（来自 YAML）
详见：`dify/主对话流/心语精灵-主工作流-节点详解.md`

## 需补齐节点与连线（建议）
- FAQ 答复出口：`FAQ_Answer (llm)` → `直接回复 (answer)`
- 反馈通道：
  - `Feedback_Extractor (llm)` → 新增 `反馈话术生成 (llm)` → `直接回复 (answer)`
  - （可选）`Feedback_Extractor` → 新增 `HTTP Request/DB 记录`（写入 `feedbacks` 或工单系统）
- 风险路由（条件分支 2 出口）：
  - level=4 或（level=3 且 timeframe=now 且 means_access=possible）：
    - 新增 `危机引导&安全提示 (llm)` → `直接回复 (answer)`
    - 新增 `人工转交 (HTTP Request)`：告警入 `risk_signals`，并推送至校内值班渠道（遵循授权策略）
  - level=3（非紧迫）：新增 `加强建议与回访计划 (llm)` → `行为闭环` → `直接回复`
  - level=1~2：新增 `安抚话术+自助资源 (llm)` → `行为闭环` → `直接回复`
  - level=0：回流主干（情感/语境→汇总→建议）或直接答复
- 行为闭环集成：
  - `汇总、总结与建议生成 (llm)` 的 `actionable_suggestions` → 新增 `行为任务创建 (HTTP/DB)` → 新增 `提醒/回执/回访`（参考 `dify/主对话流/行为闭环-任务创建与跟踪.md`）

## 实现要点（对齐 Dify 节点能力）
- LLM 节点：维持 `zai-org/GLM-4.5` 模型，严格结构化输出（JSON Schema）以驱动 if-else 分支与下游写入。
- 知识检索：启用 Reranker（Youdao BCE），合理配置 `top_k` 与数据集；FAQ 严格“仅证据回答”。
- Agent（SmallTalk）：按现有 MTD 策略与指令；通过 `conversation.smalltalk_count` 做频控与轻 Nudging。
- 风险评估：保持当前 Schema（level/intent_type/means_access/timeframe/...）；补齐“条件分支2”的外出连线及落点。
- 行为闭环：
  - 建议 → 行为任务：将 `actionable_suggestions` 转换为 `behavior_tasks` 记录（title/steps/due_at/alt_plan）。
  - 提醒/回执/回访：由“任务事件”子流程实现（`task_events`/`checkins`/`daily_reports`）。
  - 指标：接受率/启动率/完成率/复访改善度。
- 反馈通道：`Feedback_Extractor` 产出结构化字段 → 話术生成/入库 → 后台看板聚合。
- 人工转交：通过 `HTTP Request` 或外部队列将高危信号写入 `risk_signals`，遵循授权策略与审计留痕。
