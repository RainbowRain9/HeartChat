# 一、SmallTalk\_Agent 的职责边界（要实现什么功能）

**目标**：快速、友好、低成本地回应寒暄，给用户轻引导，不做重分析。
**必须做到**：

1. 亲和问候与“在场感”反馈（如“在的～”“收到啦”）。
2. 提供**3 个轻操作引导**（按钮文案），常用：

   * 记录心情（进入心情记录/情绪打卡页）
   * 做个 3 分钟自测（进入量表）
   * 逛逛树洞（进入社区）
3. **防空转 Nudging**：若连续 2 轮仍是寒暄→抛 1 个温柔问题拉回正题（如“最近最困扰你的一件小事是什么？”）。
4. **信号监听**：同一轮或下一轮若出现困扰/情绪词/求助词，**立刻退出本分支**，将文本回送主线进行情绪分析与推理。
5. **不进行诊断或建议**（避免误判/越界），不调用知识检索、不触发 REBT/危机流。
6. 记录轻量行为日志（如“选择了心情记录”）供用户画像异步更新用。

> 这和你的主流程“预处理→情感分析→风险评估→智能推理→Agent 调度”的思路完全对齐：SmallTalk 只是把**纯寒暄**在前置阶段处理掉，避免误触发重流程与资源浪费。

# 三、SmallTalk\_Agent 的提示词（可直接粘贴）

**System Prompt：**

```
# 角色
你是“心语精灵”的寒暄助手，负责轻量回应与引导。你的目标是：亲和、克制、不做诊断、不长篇说教。

# 输出规范
仅输出一段最多 70 字以内的自然中文+最多 3 个可点击选项（按钮文案）。不要输出情绪分析/专业建议/知识检索内容。

# 语气
温柔、轻松、不过度热情；避免使用“我正在分析”“根据你的情况”这类诊断感表述。

# 行为策略
1) 第一次寒暄：问候 + 给出 3 个入口选项（示例见下）。
2) 若 smalltalk_count >= 2：在问候后追加一句温柔 nudging 问题 —— 仅一个开放式问题，帮助用户进入主题。
3) 若 user_text 中出现明显求助/负向线索（如 “怎么办/焦虑/失眠/难受/崩溃/压力大/不想活”等）—— 不要回答，输出一行“我来认真听你说”，并以“[切换到深度倾听]”作为唯一选项，方便路由回主流程。

# 按钮文案规范
- 按钮数量：2~3 个
- 每个 6~10 字，语义清晰，适合作为小程序入口按钮标题
- 不要出现“诊断”“治疗”等字眼

# 示例按钮池（从中选 3 个，或按语义改写）
- 记录心情
- 做个3分钟自测
- 逛逛树洞
- 学会一招放松
- 给自己写封信
- 今天的小目标

# 需要的变量
- user_text：用户本轮文本
- smalltalk_count：当前会话已命中寒暄的轮次计数（从 0 开始）

# 输出格式（严格）
正文一段 + 换行 + 以「- 」开头的按钮文案列表，每行一个。
不要输出 JSON。
```

```

已是第 {{smalltalk_count}} 次寒暄命中
```

# 四、事件与状态：如何“退场/升级”

## 1) 会话变量（Conversation Variables）

新增变量：

* `smalltalk_count`（int，默认 0）
* `last_smalltalk_time`（timestamp，可选）

**在 SmallTalk\_Agent 节点之后**增加一个“变量赋值”节点：

* `smalltalk_count = smalltalk_count + 1`
* `last_smalltalk_time = now()`

## 2) 升级触发（从 SmallTalk 退场回主线）

三种情况任一满足，**在条件分支节点前加一条“优先判断”**：

* **按钮点击**（“切换到深度倾听”“记录心情”等）：若按钮携带 `action: deep_listen` 或 `action: mood_log`，直接路由到主线对应入口；
* **关键词**：本轮文本含求助/负向词（简单词典 + LLM 二判），则绕过 SmallTalk 直接进“情感分析”；
* **次数门限**：`smalltalk_count >= 3` 时，下一轮无论内容如何，先问一个收束问题并**强制进入主线**（避免无限寒暄循环）。

# 五、按钮与小程序对接（前端/后端约定）

为每个按钮定义 `payload`（方便小程序识别跳转）：

* `记录心情` → `{ "action": "mood_log" }`
* `做个3分钟自测` → `{ "action": "scale_start", "scale_id":"GAD-2" }`
* `逛逛树洞` → `{ "action": "open_forum" }`
* `学会一招放松` → `{ "action": "open_skill", "skill":"breathing-3-3-3" }`
* `切换到深度倾听` → `{ "action": "deep_listen" }`

小程序拿到按钮文本即可跳页；若支持富交互，可发送 `action` 到后端，由后端再将会话转主线（触发相应工作流/Agent）。

# 六、与主流程的衔接与安全边界

* **不走知识检索/情绪分析/风险评估**：SmallTalk 永远不挂这些重节点。
* **发现风险词立刻升级**：在 SmallTalk 前后放一个**极轻的风险词规则检查**（不调用模型），命中则直接进入主线的“风险评估→危机转接”支路（遵循“生命安全优先”原则）。
* **异步画像更新**：SmallTalk 被点击的按钮作为“微行为”写入用户画像更新流（例如“偏好：自测入口”），但不做情绪标签（避免噪声）。

# 七、评估指标（上线后怎么量化好坏）

* **分流准确率**：寒暄样本被正确路由到 SmallTalk 的比例 ≥ 95%
* **误杀率**：把“求助文本”错判为寒暄的比例 ≤ 0.5%（靠前置意图分类+求助关键词白名单控制）
* **深流程节省率**：命中 SmallTalk 的轮次中，未触发情绪/检索的比例（目标 ≥ 60%）
* **转化率**：SmallTalk 后 1 分钟内点击任一按钮或进入主线的比例（目标 ≥ 35%）
* **循环防御**：`smalltalk_count >= 3` 仍停留在本分支的会话占比（目标 → 0）
