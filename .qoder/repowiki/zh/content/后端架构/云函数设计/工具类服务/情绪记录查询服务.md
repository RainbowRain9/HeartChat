## 简介
`getEmotionRecords` 云函数为前端情绪历史页面提供分页查询支持，实现基于用户ID、角色ID等条件从云数据库检索 `emotionRecords` 集合数据的功能。该服务支持分页（limit）、排序（按创建时间倒序）和基础过滤功能，是情绪历史追踪与分析的核心数据接口。

**Section sources**
- [getEmotionRecords/index.js](file://cloudfunctions/getEmotionRecords/index.js#L1-L112)

## 请求参数说明
云函数接收以下参数以构建查询条件：

| 参数名 | 类型 | 是否必需 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `userId` | String | 是 | 无 | 用户唯一标识，用于定位用户的情绪记录 |
| `roleId` | String | 否 | 无 | 角色ID，用于筛选特定角色下的情绪记录 |
| `limit` | Number | 否 | 20 | 每页返回记录数量，用于实现分页功能 |

## 核心实现机制
云函数通过双重查询策略确保查询的兼容性和稳定性。

```mermaid
flowchart TD
Start([入口]) --> Validate["验证userId参数"]
Validate --> |缺失| ReturnError["返回参数错误"]
Validate --> |有效| BuildCondition["构建查询条件"]
BuildCondition --> TryStringQuery["尝试字符串查询"]
TryStringQuery --> |成功| ProcessResult["处理结果"]
TryStringQuery --> |失败| TryObjectQuery["尝试对象查询"]
TryObjectQuery --> |成功| ProcessResult
TryObjectQuery --> |失败| ReturnQueryError["返回查询错误"]
ProcessResult --> Sort["按createTime倒序排序"]
Sort --> Limit["限制返回数量(limit)"]
Limit --> ReturnSuccess["返回成功结果"]
ReturnError --> End([退出])
ReturnQueryError --> End
ReturnSuccess --> End
```

## 错误处理机制
云函数实现了分层错误处理，确保服务的健壮性。

```mermaid
flowchart TD
A[入口] --> B[参数验证]
B --> |失败| C[返回参数错误]
B --> |成功| D[字符串查询]
D --> |成功| E[返回结果]
D --> |失败| F[对象查询]
F --> |成功| E
F --> |失败| G[返回双重查询错误]
H[捕获异常] --> I[返回执行失败错误]
C --> J[退出]
E --> J
G --> J
I --> J
```
